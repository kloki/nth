# nth-curios

Notes for working in this crate. The root `CLAUDE.md` has the commands, the crate map and the rules every crate keeps.

repository-local static-document review, independent of sessions and UI. `Store` (`store.rs`) manages `.nth/curios/<session-id>/` at the repository root (`owner_root`, the main checkout through nth-directories, so every worktree finds the same store; `Store::open` builds a session's store from its state root): editable `source/`, private state, immutable published revisions, threads and submitted batches. `Store::new` asks one `git check-ignore` about every path it must find ignored, and walks the whole tree only when `VERIFIED`, the per-process cache keyed by the canonical root, holds no `Stamp` for the root or the base `.nth/curios/.gitignore` changed since; this session's own folder is checked on every construction, but a nested `.gitignore` added later in another session's folder goes unseen until the base `.gitignore` changes or nth restarts. A store call spawns git or waits on a lock another process holds, so async code runs one through `offload` on a blocking thread. `validation.rs` checks published HTML and `host.rs` serves the browser viewer. Use the Curios domain operations rather than editing private state or revisions. `nth-tools/src/curios/` supplies `curio_read`, `curio_publish` and `curio_reply`, which open the calling session's store from `ToolContext`'s `state_root` and `session` on a blocking thread (refused to subagents and agents that do not allow them), and the session delivers submitted feedback through the inbox. Depends on nth-directories only. The CLI is `crates/nth/src/curios.rs`; the TUI follows them in `CuriosTab` (`crates/nth-tui/src/curios/`: the polls, acknowledgments and openings as jobs, the browser hosts and the `/curios` picker, `picker.rs`), whose `next()` hands the loop a finished job or, once a second while no poll runs, a poll that is due; its first poll finds the repository on its blocking thread, never on the loop (only a `RepoRequired` answer stops the polling, and with it the tick; another git failure is asked again), and `app/curios.rs` applies its steps to the session, the inbox, the hints and the input panel.
