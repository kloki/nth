# nth-protocol

Notes for working in this crate. The root `CLAUDE.md` has the commands, the crate map and the rules every crate keeps.

types every crate shares: `Message`, `Event`, `Mode` (plan or act), and the `Provider` and `Tool` traits. Anything swappable sits behind one of these traits. `Provider::qualify` names a hand-written model id (an agent's frontmatter) as the listing does, `provider/model`; the default leaves it as it is and `Providers` routes it. It re-exports `nth_context::agents::tool_names` (`WRITERS`, `writes_files`, `touches_work`, `WORK_TODO`, `UNTIMED`), the names that agent permissions, plan-mode subagents, the session loop and the TUI decide on. A failed call's `Message::ToolResult` carries `is_error` (saved only when set), since a result that succeeded may start with the same `Error: ` text: `Message::tool_failed` writes one (the reason after `Error: `, for the model), `Message::tool_result` a success, and `failure_reason` (`tool.rs`) reads the reason back from the flag, never the text (the usage ledger and the TUI's replay do). `tool.rs` also has `INTERRUPTED`, the reason when you cut a call short, and `timed_out`, when the loop's ceiling does. `parse_args` turns any tool's arguments into its struct. `ToolContext::for_call` is the context one call runs in, which `run_call` builds: a clone of the turn's with its own `cwd` (where an earlier step moved the session), asker tag, output and attachments, so a field added later is shared by default. `ModelSettings` (`provider.rs`) is a model with what the listing says of it (window, output limit, `takes_images`, cost; `sized` from a `Listing`, `bare` before one), and `ChildLlm` on `ToolContext` is what a tool that starts another session starts it on: the session's own `ModelSettings`, the subagent and clerk picks and the compaction policy, `for_agent` choosing the clerk's, else the subagents', else the session's own. Also the handles a tool reaches the front-end through, on `ToolContext`: `Asker` (questions), `Screen` (which tab shows), `Monitors` (`monitor/`: the wire types and the registry of running commands, which only passes what they say to the front-end), `Wakeup` (`wakeup.rs`: the session's one replaceable deadline, at most `Wakeup::MAX`, an hour, which a front-end enables and watches; the default is disabled, as headless) and `Attachments` (`image.rs`: the `Image`s a tool shows the model beside its text, one per call, which `run_call` puts on the `Message::ToolResult`; an image's bytes live in a file of their own, `path`, and ride along base64 in `data`, which is never saved). `context_preview.rs` (its types re-exported at the crate root) holds the typed next-request `Preview` (its `Entry`s, `ToolDefinition`s, `Budget` and the `Phase` of the turn it was taken at, whose `label()` the TUI shows) and `ContextPreview` (also on nth-session's `FrontEnd`), a `watch` slot holding the newest `Arc<Preview>` the loop published; `builds()` is whether a front-end subscribed or the `context` tool asked (`want`, which the loop's `turn_ended` clears, since a front-end's slot outlives the turn); `reset` empties the slot and the want as a turn or `/compact` starts (and the TUI's as its turn ends, even a panicked one), so whatever it holds during a turn is that turn's; a headless turn builds none until something asks, and a front-end holds a receiver only while its context tab is open during a turn, since one kept between turns would have every later turn build. `Workdir` on `ToolContext` is where a tool moves the session's working directory (the worktree tools), shared by the calls of a turn.
