# nth-directories

Notes for working in this crate. The root `CLAUDE.md` has the commands, the crate map and the rules every crate keeps.

checkout and main-checkout discovery (`project_root`, `main_project_root`, `main_checkout`; nth-context's walks, nth-lsp's and nth-format's roots and the worktree tool ask it directly) and the main checkout's `.nth` layout: every path to that state is a `Directories` accessor (`config`, `plan`, `session_work`, `memory`, `curio_owner`, `curio_source`, `curio_revisions`, `curio_revision`, `worktrees`, `worktree_setup` and the rest), never a literal at the call site; tests may spell the layout out to pin it. The exception is nth-context's walk tables, `.nth/skills` and `.nth/agents` beside `.claude/skills` and the others, looked for in every directory of the walk rather than in the main checkout. A session persists its state root so plans and work remain in the main checkout across worktree moves and removal; non-Git sessions use their starting directory. Checkout-specific project discovery remains separate. The Curios store is always in the main checkout of a session's state root. Also how a path the user types is read: `expand_home`, the one `~` rule the config, the tools, instruction imports and `/add-dir` share, and `added` (`expand`, `validate`, `resolve`), the directories `/add-dir` and `[directories]` add beside the working directory. Depends on nothing else in the workspace.
