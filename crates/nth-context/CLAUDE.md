# nth-context

Notes for working in this crate. The root `CLAUDE.md` has the commands, the crate map and the rules every crate keeps.

what nth reads about a project before the first prompt: instruction files (`AGENTS.md`, or `CLAUDE.md` where a project has none), skills (`SKILL.md` folders in the Claude Code, opencode, open-standard and nth places, plus the internal ones nth ships in `skills/internal/` (`init`, opencode's `AGENTS.md` setup; `setup-worktrees`, which writes `.nth/worktree-setup`; `work-plan`; `config`, how to set up `config.toml`; `browser`, which drives a browser with the agent-browser CLI through bash; `screenshot`, which captures the screen, a window or a region with the platform's CLI and reads the file; `curios`, how to author, publish and revise a curio from review comments; `curios-design`, the page contract a curio must keep to and how to design it and draw its diagrams, adapted from Claude's artifact design skills), which a skill file of the same name replaces) and agents (`agents/`: opencode's built-in `general` and `explore`, nth's `clerk` for small one-off tasks such as a commit message, nth's `experimenter`, which settles a question by running something in a git worktree of its own, nth's primary `research` agent, which splits a long investigation across subagents and keeps its findings in `.nth/research/<session>.md`, shown with `show_user`, plus one markdown file per agent in the Claude Code, opencode and nth places, the body being its system prompt; opencode's `mode` frontmatter makes one a `Subagent` (the default), a `Primary` agent you run a session as in place of plan or act (never named `plan` or `act`), or `All`, and `Agents::subagents` and `Agents::primaries` are what the task tool and `/agents` offer), and the project's memory (`memory.rs`: `.nth/memory/` in the main checkout, so worktrees share it, one markdown file per fact with `name`, `description` and `type` (user, feedback, project or reference) frontmatter, and `MEMORY.md`, the index, cut to 200 lines or 25 KB for the system prompt; read only when `Paths::memory`, the config's `[memory] enabled`, is on), found by `Context::discover`, the instruction walk going from the working directory up to the home directory when under it, else to the project root, and the nested ones the read tool attaches (`instructions::nested`, from the folder of a file read or a directory listed); each file brings the ones it names with `@path` outside code (`instructions/imports.rs`, Claude Code's rule: relative to the file, `~` for home, 4 files deep, each file once, a word naming no file left alone since `@explore` is an agent). `instructions::Watch` is what a session's model last saw of those files and of where one more could appear (`Context::absent_instructions`): asked with a stat per file, it returns the files created, edited or removed since. `frontmatter` reads the YAML block skills and agents share. `Paths` carries the home, config and data directories so tests never touch the real ones; `Paths::nth_data` is where nth saves (sessions, `models.json`, the models.dev catalogue kept between runs, and `auth.json`, whose `Store::new` takes it from the CLI). Depends only on nth-directories, for where a project and its `.nth` are.
