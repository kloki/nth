# nth-lsp

Notes for working in this crate. The root `CLAUDE.md` has the commands, the crate map and the rules every crate keeps.

language server diagnostics, LSP written by hand (`transport`, which refuses a message past `MAX_MESSAGE_BYTES` before allocating it, `types`, `client/`). `server/` is opencode's server table (rust-analyzer, typescript-language-server, gopls, pyright and more, used only when on PATH) plus `[lsp]` from the config, with the project-root rules. `Lsp` is one process-wide, cheap-to-clone pool: `touch(path, wait)` starts a client per (server, root) on first use (stopped again once untouched for `[lsp] idle_secs`) and returns the diagnostics (a server that dies, or takes no touch within `TOUCH_TIMEOUT` having stopped reading what it is sent, is dropped from the pool and killed through its entry's cancel token, its status broken with the reason — the unreadable message, else its stderr read to the end — until the next touch starts it again, at most `MAX_RESTARTS` (3) times per root, never reset, after which it stays broken until nth restarts; one that fails to start is not tried again; a start holds the pool weakly, so dropping the last `Lsp` cancels it and kills its server), `status()` is a `watch` of every client's state, `usage()` a `watch` of each server's process and callers, and `report` writes opencode's text for the model. `pool/mod.rs` is the clients' lifecycle, `pool/idle.rs` the touch accounting and idle reaper, and `pool/usage.rs` the usage types, `snapshot` (taken under the clients lock, published after it is released, since a watcher's borrow holds up the publish) and the sampler, a one-second tokio interval the pool owns and aborts when it goes, running while anyone subscribes and reading `/proc` on a blocking thread only for the read. `nth lsp` prints `Lsp::servers_for`.
