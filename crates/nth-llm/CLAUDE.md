# nth-llm

Notes for working in this crate. The root `CLAUDE.md` has the commands, the crate map and the rules every crate keeps.

`Provider` impls. One module per wire protocol, each a `Client` that streams one request: `chat_completions` (OpenCode Go or any OpenAI-compatible endpoint, and what a model goes over when the catalogue says nothing else; a tool call a server sends without an id gets `call_<random>_<index>`, the random part one per reply so a history never holds an id twice), `messages` (Anthropic messages, for Claude on Zen and MiniMax on Go) and `responses` (OpenAI responses, for GPT on Zen and GPT and Grok on Go). `providers/` is the one `Provider` the front-ends see: an `Endpoint` per `[provider.<id>]` in the config (`endpoint.rs`), each with its three clients, a `Kind` (`Configured`, its key and models, or `ChatGpt`, the login and the efforts its last list offered) and `Endpoint::stream`, which readies a request for the model's wire and sends it, and `listing.rs` for its `/models` and the merged listing. An endpoint signs requests with its `Credentials` (`auth.rs`): an API key, or `ChatGpt` from nth-auth, resolved once per request (refreshing the token) and put on the wire by each client (for ChatGPT the bearer token alone; a plan refusal no wait fixes, such as `subscription_sharing_usage_limit_exceeded`, is never retried, `responses::REFUSAL`); a login that fails is a request error (`stream::Error::Auth`), retried only when the token server could not be reached or answered a 429 or a 5xx, never when you must sign in again or it refused otherwise. `chatgpt.rs` is the one built-in endpoint, `chatgpt`, on OpenAI's public Responses API with a Sign in with ChatGPT token: always responses, OpenAI's catalogue entry for what a model needs on the wire, and its models from OpenAI's list (`GET /v1/models`, which differs by plan and account: the listed, API-supported ones, with its context window and efforts and the catalogue's output limit) at no price; the endpoint remembers the efforts its last list offered, and `stream` snaps a request's effort to those before the catalogue's. It is always among the endpoints but asked `connected()` each time: until then its models are refused (`providers::Error::Auth`) and it is left out of the listing, so connecting mid-run needs nothing rebuilt. A model id is `provider/model`: the prefix routes the request to its endpoint and the rest goes on the wire, and a bare id goes to the default provider (the config model's). `catalog` is models.dev, fetched in the background when `Providers` is built and kept once loaded (`Snapshot`; never by `Providers::offline`, which `nth context` and tests run on); a failed fetch leaves none: callers during the backoff (5 s doubling to 5 minutes, `RETRY_INITIAL` and `RETRY_MAX`) get none at once, callers during a fetch wait on it rather than start their own, and the background task (`Snapshot::refresh`) fetches again as each backoff runs out until one loads, a caller that finds one due first fetching itself, waiting up to the fetch's 5 s timeout. Every fetched catalogue is kept at `models.json` in the data directory (written aside and renamed over; `Providers::new`'s `cache`, which `Runtime::providers` passes), and read back on a blocking thread before the network is asked, by the background task first and by a request that finds nothing served, and served at once, stale but routing each model over its protocol, while the background task keeps trying the network until a fetch replaces it; no request waits on the network while it serves. Its entry for an endpoint is the one with its `base_url` as `api`, else the one keyed by its config id (`provider_for`, so `[provider.openai]` finds OpenAI's); an endpoint with no entry borrows a model's name, limits and efforts from another provider's (`borrowed`: by id, else the part after the last `/`, preferring the `canonical_model_id`), never its price or wire. The listing reads names, limits and the efforts a model takes (`reasoning_options`) from it, and `stream` snaps the request's effort to the nearest of those and dispatches on the `Wire` its SDK for the model maps to, handing the protocol the catalogue's entry for what it needs (an output limit, whether the model reasons, adaptive thinking or a budget on messages). Whether a model takes images is the catalogue's `modalities.input` (`ModelInfo::takes_images`, `None` for a model it does not know, which is sent images; ChatGPT's from OpenAI's `input_modalities`), and `providers/images.rs` rewrites a request's images before it goes out: one whose file was gone at load, one over `MAX_IMAGE_BYTES` (Anthropic's 5 MB of base64), or any for a model that takes none, becomes a note in its result's text, and past 25 MiB or 50 images the oldest become the removal note down to 15 MiB, never those of the latest run of results unless they alone are too many. messages and responses carry a tool result's images inside it; chat completions sends them in one user message after a run of results, since some servers take only text in a `tool` message. A model it does not know, or no catalogue at all, goes over chat completions; one whose protocol nth does not speak (Gemini's) is not listed. A chat completions request carries the session id as `prompt_cache_key` only for a provider on its allowlist of models.dev ids (`chat_completions::takes_cache_key`, asked through `Endpoint::takes_cache_key`), since strict servers refuse unknown fields. `http` is what the protocols share on the wire: the one `reqwest` client, the user agent, the session headers (`x-opencode-session`, `x-opencode-session-id` and, for a subagent, `x-opencode-parent-session-id`), the deadlines and the HTTP facts that decide a retry; `sse` is the line splitting and the `Parser` their streams share, each protocol's `event.rs` giving it, as a plain fn, the events one line holds. `stream` is the rest they share: `Client` (the endpoint's base URL and the route each protocol's own `Client` builds it with) and `send`, the status check (a `Refusal` saying how the protocol reads a refused body), the one `events` loop each protocol's `State` drives as a `Protocol`, `cut`, how each ends a reply cut at the output limit (its text kept as an answer with a note, its tool calls dropped since their arguments are partial), and `Error`, one plain error for every protocol: each classifies what it reports in-stream as it reads it (its `provider_error`, into `Error::Provider` with `retryable` and `overflow`), so `retry_boxed`, which `Providers::retry` calls, reads one type.
