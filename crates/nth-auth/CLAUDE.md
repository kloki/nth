# nth-auth

Notes for working in this crate. The root `CLAUDE.md` has the commands, the crate map and the rules every crate keeps.

signing in to providers that take an account rather than an API key. `Store` is `auth.json` in the data directory (opencode's shape, one entry per provider id, written aside and renamed over with mode 0600). `ChatGpt` is a ChatGPT subscription signed in with OpenAI's Sign in with ChatGPT: `login` runs OAuth with PKCE in the browser (a callback server on `127.0.0.1:1455`, or a free port if taken, written by hand, the pages in `templates/`; a request without the login's `state` is answered 400 and the login goes on waiting, so only the issuer's redirect, a code or an `error`, ends it; it registers nth's own client on the first sign-in and reuses the issued client ID (never the `dynamic_agent_client` entrypoint), keeps a stable host ID beside `auth.json`, sends the saved ID token as the next sign-in's hint, and checks the ID token against the JWKS its OpenID configuration names before replacing a different account's credentials), `credentials` reads the store on every call and refreshes a token about to run out (one refresh at a time across clones, so a process keeps one handle and clones it), `logout` revokes the refresh token (network errors and 5xx tried again), clears the tokens either way and returns `SignedOut::Unconfirmed` when OpenAI did not confirm, `connected` says whether there are tokens with a client ID (a login from the old Codex flow, or one whose refresh token OpenAI has revoked, asks to sign in again). Depends on nothing else in the workspace.
