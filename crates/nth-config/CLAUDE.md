# nth-config

Notes for working in this crate. The root `CLAUDE.md` has the commands, the crate map and the rules every crate keeps.

`Config` and its sections (`lib.rs`), what `config.toml` and a repository's `.nth/config` hold, every key optional and unknown ones refused; `TEMPLATE` is the `nth init` template (`config.toml`), and tests keep it, the defaults and the internal `config` skill's reference agreeing. `layers.rs` layers the global file (`Config::default_path` in `Paths`' config directory, or `--config`) and the repository's (`repo_config`: the main checkout's in Git, else the nearest from the working directory up to home) into one: a repository may set only the allow-listed sections (`read_layer`), its `skills.paths` and `directories.paths` resolved component by component through symlinks (`resolve_path`, dangling links followed, a loop an error) and refused outside its root (`paths_inside`), and those two lists append while everything else merges as tables. `Config::load_in` takes the `Paths` to read from, so tests never touch the real home. `selection.rs` is `Selection`, what every kind of turn runs on and the one copy of its rules, plain data with no provider: `Slots` (plan, act, and the optional subagent and clerk), the mode and the primary agent running in its place (`pub` fields), each agent's model for the run (`set_agent`: what it was pinned on — picked by hand, act picked while it runs, or left on — else its own model at act's effort, else act's, which a profile cycle moves along with act until then), `current` (the agent's, else the mode's), `llm(Target)` (subagents fall back to the current, the clerk to the subagents'), the qualified `Profile`s and `next_profile`, which returns `Cycled` for the front-end to say. `Selection::from_config` builds it with the provider's `qualify` and `check` passed in as closures (`nth/src/runtime/llms.rs`), from the helpers on `Config` (`profile_llm`, `profile_subagent`, `profile_clerk`); `needs_model` says when a random model fills `model` first. `Target` (plan, act, agent, subagent, clerk) is what the model picker's Tab cycles. Both front-ends read it: the `nth` crate loads it, and the TUI reads its own sections off the `PreparedRuntime`.
