# nth

Notes for working in this crate. The root `CLAUDE.md` has the commands, the crate map and the rules every crate keeps.

the clap CLI; with no subcommand it opens the TUI, `run` prints events with `render.rs`. A command that prints what it found prints it through `output.rs`, in three parts: a `<Command>Report` struct with the values it prints, owned or borrowed (never a handle it would ask while printing, so `nth connect --status`'s holds whether ChatGPT is connected, not the login), with `impl Report` giving its `text` and `json` halves (`json` writes rather than returns a `Value`, so a JSON line per entry fits as well as one document); a gather step that takes `cwd: &Path` and the config as arguments rather than reading `current_dir` itself; and `run`, which gathers, hands the report to `output::print` (JSON when `--json` is given or stdout is not a terminal) and then applies any exit decision, outside `Report` (`nth worktree cleanup` failing when a removal did). `work`, `session list`, `context`, `worktree cleanup`, `connect --status`, `curio`, `skills`, `agents`, `memory`, `formatters`, `lsp`, `models`, `notify` and `usage` print this way; `skills` and `agents` share `text.rs`'s `place`, `groups` and `nested_folder`, and all three its `branch`. Its tests build the report directly: the text as an `insta` snapshot of `output::testing::text` (colours and trailing spaces stripped) in `crates/nth/src/snapshots/`, one test per snapshot on the smallest fixture with fixed ids, paths and `now`; the JSON through `output::testing::json`, with field asserts plus one `assert_json_snapshot!` per command of a whole line or document (`context` excepted, its text and JSON carrying the tools' descriptions, so it keeps `contains` checks); a snapshot changes only by accepting its `.snap.new` by path after reading it. `runtime/` is the one way a session starts, for the chat (at start and on `/resume`, through `Runtime::reload`, the TUI's `Reload`), `nth run` and `nth context`: `Runtime` keeps the config path, `--model`, the global directories (`Paths`, read from the environment once; the config's loading, `prepare` and the login take theirs from them, so tests point them at a temporary folder) and the process's one `nth_auth::ChatGpt` (`Runtime::chatgpt`, built on first use; the providers' endpoint, `/connect`, every `/resume` and `nth connect` take clones of it, so one token is refreshed once), `Runtime::config_for` loads the config for where a `Start` (`Fresh` or `Saved`) runs, `Runtime::providers` builds the providers from it (`nth context` passes offline ones), and `Runtime::prepare` returns the `nth_tui::PreparedRuntime`: the session with its context, qualified model, directories, limits and compaction, a model picked when the config names none (a warning), each mode's llm with a saved session's on its mode, the profiles, the one tool list (`runtime/tools.rs`, the task tool included, every tool an `Arc<dyn Tool>` so the task and work tools hand subagents the same ones), the shell and the config itself, which `prepare` takes by value and hands on. `config.rs` is only `nth config` and `nth init`, over `Runtime::config_file` and `Runtime::env`; `nth skills` and `nth agents` read `Runtime::paths`, so these commands take the global directories only from the `Runtime` (the session store, `Store::open`, and the TUI's `HOME` still read the environment). `nth run` sizes the session from a listing once its `--agent` switch makes the model final. Its binary tests (`crates/nth/tests/`) start the `nth` binary only through `support::Env` (`tests/support/mod.rs`), which clears that child's environment, points its `HOME`, `XDG_DATA_HOME` and `XDG_CONFIG_HOME` into a temp dir and kills it if it hangs, so no run of `nth` in a test reaches your own config, sessions or `.nth` (other programs a test runs itself, such as `git init`, still inherit the test's environment); `Env::redact` names that dir `[root]` for the insta snapshots in `tests/snapshots/`.
